# M18.3 — Production Convergence Preparation v1.0

Status: PREPARED / NOT DEPLOYED
Date: 2026-09-24

## Objective
Prepare a production-bound M18 runtime without modifying the live M17 gateway or granting HTTP callers agent-creation/approval authority.

## Boundary
- M17 remains unchanged and isolated on `ollama_default`.
- M18 candidate runtime shares `peyzaj_production_peyzaj_net` with n8n for internal HTTP access and `ollama_default` for model execution.
- No host port is published.
- M18 registry authority is persistent PostgreSQL state, not in-memory bootstrap state.
- Human approval is required for Core Agent creation.
- The production HTTP surface accepts only `prompt` and `requires_human`.
- `APPROVE` and `PROVISION` are never accepted as caller controls.

## Critical blocker before M18.4
`migrations/nonprod/014_m18_agent_registry_authority.sql` is explicitly non-production and begins with `DROP SCHEMA ... CASCADE`. It MUST NOT be run against `peyzaj_postgres`.

Before M18.4, a separate production-safe, idempotent migration must be produced and reviewed. Production DB credentials/roles must also be provisioned without embedding secrets in Git.

## Candidate artifacts
- `runtime/m18_production_gateway.py`
- `runtime/Dockerfile.m18-production`
- `runtime/compose.m18-production.yml`

These artifacts are deployment candidates only. They do not change the live host until M18.4 is explicitly executed.

## Convergence model
1. Production-safe migration creates the M18 registry schema/tables/policies idempotently.
2. A dedicated runtime DB login is granted only the orchestrator runtime role; it cannot create CORE agents.
3. Human approval path creates CORE agents through a controlled database procedure/process.
4. Orchestrator runtime may provision bounded SPECIALIST agents only under an existing CORE parent.
5. Runtime starts only when `M18_AGENT_ID` resolves to an ACTIVE QWEN specialist.
6. n8n reaches M18 over the private production network; M18 has no public host port.
7. Ollama access remains on the existing model network.

## Rollback
- Stop/remove only `m18-runtime-gateway`.
- Do not restart, replace, or modify `m17-runtime-gateway`.
- Do not roll back the main production Postgres container.
- Any registry migration must be backward-compatible and independently reversible before production execution.

## Go / No-Go for M18.4
GO only if all are PASS:
- GitHub branch synchronized and clean.
- Production-safe migration reviewed; no destructive statements.
- Dedicated DB principal and secret injection verified.
- Human Core approval path verified.
- Existing specialist identity recorded.
- M18 container builds from repository.
- M18 health check succeeds.
- M18 cannot reach M17 container by network design.
- M18 can reach Ollama and production PostgreSQL only as required.
- HTTP security tests pass.
- Live M17 E2E remains unchanged before/after deployment.
- Explicit rollback command tested in the isolated candidate environment.
