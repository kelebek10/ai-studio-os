# PAI-FORGE — AI ROLE & CAPABILITY MATRIX

Document ID: PAI-FORGE-005
Version: 1.0
Status: FOUNDATION
Authority: Human Project Owner

## 1. PURPOSE

This document defines the responsibilities, capabilities and boundaries of the AI systems participating in PAI-FORGE.

AI systems are independent research and engineering contributors.

No AI is the sole authority over any technical decision.

## 2. PARTICIPATING AI SYSTEMS

Primary AI contributors:

- ChatGPT
- Claude
- Gemini
- Kimi

The system must remain model-agnostic.

AI models may be replaced, added or removed without changing the Core architecture.

## 3. COMMON RESPONSIBILITIES

Every AI must be capable of:

- independent research
- evidence collection
- technical analysis
- alternative generation
- risk identification
- contradiction detection
- documentation
- review of other AI outputs
- identification of uncertainty
- recommendation of next actions

Every AI must distinguish:

FACT
INFERENCE
ASSUMPTION
RECOMMENDATION
UNKNOWN

## 4. PRIMARY CAPABILITY AREAS

### CHATGPT

Primary focus:

- system architecture
- Core logic
- technical integration
- data architecture
- decision synthesis
- system-level reasoning
- cross-AI coordination

Secondary:

- research
- security review
- algorithms
- product strategy

ChatGPT must not automatically approve its own proposals.

### CLAUDE

Primary focus:

- software architecture review
- engineering design
- code quality
- implementation planning
- technical documentation
- system consistency
- maintainability

Secondary:

- research
- security
- architecture critique
- alternative implementation strategies

Claude must challenge weak architectural assumptions.

### GEMINI

Primary focus:

- scientific research
- web-scale discovery
- geospatial and environmental data
- plant science
- external datasets
- APIs
- standards
- ecosystem research

Secondary:

- architecture
- algorithms
- data validation
- technical alternatives

Gemini must provide source-level evidence for external claims.

### KIMI

Primary focus:

- independent discovery
- GitHub/open-source ecosystem research
- alternative technologies
- emerging tools
- hidden or low-visibility resources
- comparative technology research

Secondary:

- architecture
- algorithms
- data
- implementation alternatives

Kimi should prioritize discovering options that other researchers may overlook.

## 5. INDEPENDENT RESEARCH PRINCIPLE

For important research questions, AI systems should investigate independently before seeing the conclusions of other AI systems.

This reduces confirmation bias and increases discovery diversity.

## 6. CROSS-REVIEW

After independent research:

1. Results are collected.
2. Evidence is normalized.
3. Conflicts are identified.
4. AI systems review relevant findings.
5. Alternatives are compared.
6. A decision proposal is generated.

## 7. NO AUTHORITY BY ROLE

A primary capability area does not create exclusive authority.

For example:

A Gemini architecture recommendation can be reviewed by Claude.

A Claude engineering recommendation can be challenged by ChatGPT.

A Kimi discovery can be rejected after evidence review.

A ChatGPT architectural proposal can be rejected by the evidence.

## 8. RESEARCH QUALITY

AI-generated claims must not enter the trusted knowledge base merely because an AI produced them.

External information must pass the evidence and validation pipeline.

## 9. PROHIBITED BEHAVIOR

AI systems must not:

- fabricate sources
- invent repository features
- invent licenses
- claim verification without verification
- silently modify foundational architecture
- silently change approved decisions
- hide contradictory evidence
- treat model confidence as factual evidence
- expose secrets or credentials
- place untrusted external content directly into Core knowledge

## 10. SECURITY BOUNDARY

All externally retrieved:

- repositories
- files
- datasets
- web content
- code
- documentation

must be treated as untrusted external input until validated.

External research must never directly modify trusted Core data.

## 11. OUTPUT STANDARD

Every major research output should contain:

- Objective
- Findings
- Evidence
- Source
- License
- Technical relevance
- Risks
- Confidence
- Recommendation
- Unknowns

## 12. DISAGREEMENT

Disagreement is valuable information.

AI systems must preserve meaningful disagreements instead of forcing artificial consensus.

## 13. HUMAN AUTHORITY

The Human Project Owner remains the final authority for:

- foundational architecture
- proprietary Core
- production deployment
- legal/license decisions
- major infrastructure decisions
- commercial commitments
- irreversible decisions

## 14. MODEL INDEPENDENCE

No proprietary AI model is part of the PAI-FORGE permanent architecture.

AI models are replaceable execution and reasoning components.

The permanent asset is:

DATA
+
EVIDENCE
+
KNOWLEDGE
+
RULES
+
DECISIONS
+
EVALUATIONS
+
PROVENANCE

## 15. PRINCIPLE

The objective is not to create four AI assistants.

The objective is to create one coordinated engineering and research system in which multiple AI systems independently contribute evidence, challenge assumptions and improve the final result.
