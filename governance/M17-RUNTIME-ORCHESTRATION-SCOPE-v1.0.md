## 1. Scope

M17 turns the verified M16 runtime components into one deterministic, auditable mission loop without granting new authority.

Target path:

`Telegram intent → TaskEnvelope → Router → Worker/Model → Review → Evidence → Security/Human Gate → Result`

M17 is runtime orchestration work. It does not reopen M16 and does not authorize production migration or protected governance mutation.

## 2. Acceptance Criteria

- [ ] M17.1 baseline/pre-flight evidence recorded.
- [ ] One deterministic end-to-end mission loop executes from a validated TaskEnvelope to a terminal result.
- [ ] Every state transition is explicit and fail-closed.
- [ ] Model output remains untrusted data.
- [ ] Review and evidence stages cannot assert human approval.
- [ ] Conflict handling remains bounded at three rounds.
- [ ] Duplicate task delivery is idempotent.
- [ ] Evidence contains task/correlation lineage.
- [ ] Telegram remains transport only.
- [ ] A real Qwen3 execution is introduced only after the deterministic loop passes.
- [ ] No production migration or protected governance mutation occurs inside M17 without a separate approved gate.

## 3. First Controlled Task — M17.1

Build and execute a dependency-free runtime mission-loop harness using the existing M16 components.

Required path:

`VALIDATED → ROUTING → EXECUTING → REVIEW → EVIDENCE → COMPLETED`

Required negative controls:

- invalid transition;
- unauthorized route;
- model approval assertion;
- missing evidence;
- duplicate delivery;
- conflict round 4;
- undeclared Human Gate.

Evidence must be generated by real execution on the project host.

## 4. Risks

1. **Stale local state:** mitigated by syncing to remote M16 closure before implementation.
2. **Authority leakage:** mitigated by explicit router/model/security boundaries and negative tests.
3. **Hidden dependency on pytest:** mitigated by a dependency-free M17 harness.
4. **Production coupling:** prohibited during initial M17 implementation.
5. **AI output treated as authority:** blocked by existing model/security contracts.

## 5. Definition of Done

M17.1 is PASS only when the harness executes successfully on the project host and records both positive and negative controls with immutable commit evidence.

The M17 implementation branch must remain clean between controlled changes.

## 6. Boundary

M16 remains immutable. Any suspected M16 regression is evidence-first and does not silently reopen M16.
