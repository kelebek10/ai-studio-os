## 1. Objective

Define the canonical durable task-control model before any runtime or production DB mutation.

M19.1 establishes the contract; M19.2 will implement persistence only after this design is accepted.

## 2. Canonical lifecycle

The existing runtime states remain authoritative and are extended at the control-plane level with non-execution lifecycle states:

`CREATED → ASSIGNED → ACKNOWLEDGED → VALIDATED → ROUTING → EXECUTING → REVIEW → EVIDENCE → RESULT_SUBMITTED → VERIFIED`

Terminal/control outcomes:

- `COMPLETED`
- `REWORK_REQUIRED`
- `BLOCKED`
- `HUMAN_ACTION_REQUIRED`

Human Gate is represented as a controlled state:

`EVIDENCE → HUMAN_ACTION_REQUIRED`

A human action may only produce an explicitly authorized transition defined by a future Human Gate contract. No AI/provider may generate that transition.

### Compatibility rule

The current `TaskState` implementation remains unchanged in M19.1. The new control-plane lifecycle is a contract around it, not an authorization bypass.

## 3. Command vocabulary

Only canonical commands may mutate lifecycle:

- `CREATE_TASK`
- `ASSIGN_TASK`
- `ACK_TASK`
- `VALIDATE_TASK`
- `START_EXECUTION`
- `SUBMIT_RESULT`
- `SUBMIT_REVIEW`
- `RECORD_EVIDENCE`
- `REQUEST_HUMAN_ACTION`
- `RESOLVE_HUMAN_ACTION`
- `MARK_VERIFIED`
- `REQUEST_REWORK`
- `BLOCK_TASK`
- `CLOSE_TASK`
- `RECOVER_TASK`

Commands are intent records. They do not grant authority beyond the caller's existing permissions.

## 4. Event vocabulary

Every accepted command produces a durable event or an explicit rejected-command record.

Core events:

- `TaskCreated`
- `TaskAssigned`
- `TaskAcknowledged`
- `TaskValidated`
- `TaskExecutionStarted`
- `TaskResultSubmitted`
- `TaskReviewSubmitted`
- `TaskEvidenceRecorded`
- `HumanActionRequested`
- `TaskVerified`
- `TaskReworkRequired`
- `TaskBlocked`
- `TaskRecovered`
- `TaskClosed`

Events are facts, not model opinions.

## 5. Event envelope

Every event MUST contain:

- `event_id`
- `event_type`
- `task_id`
- `correlation_id`
- `causation_id`
- `sequence_no`
- `occurred_at`
- `actor_type`
- `actor_id`
- `source_commit`
- `scope`
- `payload_digest`
- `idempotency_key`

Optional:

- `parent_task_id`
- `attempt_id`
- `evidence_refs`
- `failure_code`

No event may silently change an earlier event.

## 6. State transition rules

### Creation
`CREATE_TASK` → CREATED

Duplicate `idempotency_key` must return the original task result, not create a second task.

### Assignment
CREATED → ASSIGNED only when registry, provider, scope and authority checks pass.

### Acknowledgement
ASSIGNED → ACKNOWLEDGED only by the assigned executor.

### Validation
ACKNOWLEDGED → VALIDATED only when required task identity, scope, evidence and prohibited-action fields are valid.

### Execution
VALIDATED → ROUTING → EXECUTING.

### Result
EXECUTING → REVIEW → EVIDENCE → RESULT_SUBMITTED.

### Verification
RESULT_SUBMITTED → VERIFIED only through the designated verification boundary.

Verification cannot be asserted by provider output.

### Rework
RESULT_SUBMITTED → REWORK_REQUIRED.

Rework creates a new controlled attempt while preserving the original task lineage.

### Human action
EVIDENCE → HUMAN_ACTION_REQUIRED only when the task explicitly requires human action and SecurityGate permits escalation.

### Block
Any non-terminal state may transition to BLOCKED only through a defined blocking reason.

### Close
Only a verified result may enter COMPLETED/CLOSED semantics.

## 7. Idempotency

Idempotency key is mandatory for externally submitted commands.

Canonical uniqueness:

`(task_id, command_type, idempotency_key)`

Duplicate command:

- must not execute the side effect twice;
- must return/replay the original outcome;
- must preserve event sequence;
- must not create a second attempt unless explicitly commanded.

## 8. Attempt and recovery model

Each execution attempt has:

- `attempt_id`
- `task_id`
- `attempt_no`
- `started_at`
- `acknowledged_at`
- `finished_at`
- `executor`
- `source_commit`
- `status`

Recovery must never overwrite history.

A failed attempt becomes historical evidence; recovery creates a new attempt linked to the same task lineage.

## 9. Provenance

Task lineage:

`task_id → command → event → attempt → result → review → evidence → verification`

Correlation IDs remain stable across the task lifecycle.

Child tasks retain `parent_task_id`.

Evidence references must point to the exact producer/result lineage.

Artifact and evidence digests remain mandatory where artifact integrity is claimed.

## 10. Human Gate

The control plane may **request** human action.

It may not:

- simulate approval;
- infer approval;
- accept provider `APPROVED`;
- convert model output into authorization;
- create human authority;
- bypass SecurityGate.

Human Gate resolution requires an explicitly authenticated human action under the existing authority model.

## 11. Conflict control

Existing maximum conflict rounds remain **3**.

Round 4 or higher:

`BLOCKED`

No automatic retry may convert a conflict block into execution.

## 12. Fail-closed rules

Execution must stop when:

- task identity is incomplete;
- assignment is missing;
- source commit is stale/unknown;
- scope is ambiguous;
- authority does not match;
- required evidence is missing;
- event sequence is inconsistent;
- idempotency state conflicts;
- provenance is broken;
- provider output contains approval authority;
- Human Gate requirements are incomplete.

No failed control may be converted to PASS by model reasoning.

## 14. Implementation boundary

M19.1 produces design artifacts only.

**Prohibited in M19.1:**

- production schema migration;
- production container mutation;
- M18 gateway replacement;
- M17 changes;
- new Core Agent;
- provider authority expansion.

## 15. Exit criteria

M19.1 is complete when:

1. This contract is committed.
2. Existing TaskState compatibility is explicitly preserved.
3. Transition and command/event semantics are unambiguous.
4. Idempotency and recovery semantics are defined.
5. Human Gate authority remains human-only.
6. Acceptance tests are enumerated.
7. A separate implementation gate is opened for M19.2.
