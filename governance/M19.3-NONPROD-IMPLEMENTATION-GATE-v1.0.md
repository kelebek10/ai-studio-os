**Parent:** M19.2 Durable Task/Event Ledger Design v1.0

## Objective
Implement and validate the M19 durable task/event ledger only in a disposable PostgreSQL environment.

## Scope
- Create isolated m19_control schema.
- Implement task, task_event, task_attempt, task_handoff, task_idempotency.
- Enforce sequence, idempotency, immutability and controlled transition boundaries.
- Execute security, concurrency, replay, rollback and recovery tests.
- Produce reproducible evidence.

## Hard boundaries
- No production migration.
- No production DB connection.
- No M18 gateway mutation.
- No M17 change.
- No provider direct DB authority.
- No new Core Agent.

## Required tests
T01 schema creation
T02 canonical task creation
T03 exact replay
T04 conflicting replay
T05 invalid transition
T06 sequence race
T07 stale transition
T08 rollback + retry
T09 event immutability
T10 unauthorized direct mutation
T11 forged actor/scope
T12 provider APPROVED injection
T13 restart/recovery
T14 lineage/evidence integrity
T15 M17 non-regression

## PASS rule
Every applicable test must have fresh execution evidence. Any integrity, authority, replay, sequencing or recovery violation = BLOCKED.

## Exit
M19.3 closes only after all tests PASS, raw evidence is retained, hashes are recorded, and a review artifact is committed.

Production remains BLOCKED until a separate production migration gate.
