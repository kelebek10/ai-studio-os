# M19.5 PLANNING GATE v1.0

**Status:** PLANNING
**Parent:** M19.4 Deterministic Dispatcher + ACK/Lease
**Boundary:** Non-production planning only

## Scope
M19.5 will harden dispatcher recovery semantics and operational observability:
- deterministic retry/re-dispatch after lease expiry;
- recovery state transitions and lineage;
- heartbeat/lease renewal;
- duplicate-execution prevention under recovery;
- minimal audit/metrics evidence for dispatch lifecycle;
- no new agent authority and no production migration.

## Acceptance Criteria
1. Expired lease produces exactly one controlled recovery path.
2. Recovery creates a new attempt while preserving task/correlation lineage.
3. Active duplicate execution is rejected deterministically.
4. Valid heartbeat extends only the current executor's active lease.
5. Stale/wrong-executor heartbeat is rejected.
6. Re-dispatch is idempotent for the same task/recovery key.
7. Dispatch lifecycle events are auditable end-to-end.
8. Restart preserves task, attempt, lease and recovery state.
9. Existing M19.3/M19.4 controls remain non-regressed.
10. All tests run in non-production with fresh evidence; any authority or lineage violation blocks closure.

## Exit
M19.5 implementation starts only after this planning gate is accepted. Production remains unchanged.
